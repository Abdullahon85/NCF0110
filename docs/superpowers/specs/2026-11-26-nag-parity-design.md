# Паритет с shop.nag.uz, фильтры, чистка и стиль кода — решения

Дата: 26.11.2026. Владелец: «функционал как у shop.nag.uz, код свой; фильтры как у них; пустой функционал убрать;
стиль кода улучшить везде; остальное — как считаешь правильным». Код и вёрстка nag не копируются: берутся только
пользовательские возможности (что видит покупатель), реализация, тексты, вёрстка и стили — свои.

## Что взято у shop.nag.uz (по страницам, проверено 26.11.2026)
- Раздел каталога: хлебные крошки, H1 + «N товаров», подразделы, панель фильтров: бренд (галочки со счётчиками,
  «Ещё N»), статус товара (Новинка / Акция / Распродажа), наличие, цена (диапазон), характеристики трёх видов —
  список значений с галочками и счётчиками, «Да/Нет», числовой диапазон; первые 5 групп открыты, остальные под
  «Все фильтры (+N)»; сортировка; товаров на странице; плитка/список; нумерованные страницы «Назад/Дальше».
- Карточка товара: фото, название, артикул, наличие («В наличии: 9 шт», «10+ шт», «Под заказ»), цена в сумах,
  старая цена зачёркнута + «−18%», ярлык статуса, «В корзину».
- Страница товара: крошки, галерея, артикул + код товара, наличие, цена/старая цена, вкладки «Описание»,
  «Характеристики» (таблица по группам), «Сопутствующие товары», «Документация», «Отзывы», «Вопросы»; похожие товары.
- Главная: баннеры, популярные разделы со счётчиками, бренды, вкладки товаров «Рекомендуем / Новинки / Акции /
  Популярное». Страница «Акции». Информационные страницы «Покупателям» (оплата, доставка, возврат, гарантия, FAQ).
- Не берём: личный кабинет и вход покупателя, калькуляторы, подборки-ссылки, филиалы, «проектные товары» — у
  компании их нет (YAGNI). Своя игра «Соберите систему» остаётся.

## Решения
1. **Теги сливаются в характеристики.** Группа тегов (TagName) и характеристика (Feature) — одно и то же: имя группы
   + значения. Две системы путают админа и дают два набора фильтров. Миграция переносит каждую группу тегов в
   характеристику, тег — в значение, привязки к товарам сохраняются; модели, API и страница «Теги» удаляются.
2. **Фильтры — один механизм для всех списков**: раздел, бренд, поиск, акции. `GET /api/products/` (товары) и
   `GET /api/products/facets/` (группы фильтров со счётчиками) принимают одинаковые параметры. Счётчики «как у nag»:
   у каждой группы — с учётом всех остальных выбранных фильтров, кроме своей группы.
3. **Состояние фильтров — в адресе страницы** (ссылкой можно поделиться, «Назад» работает), не в localStorage.
4. **Одинаковые характеристики подразделов объединяются** на странице родительского раздела: «Цвет» из трёх
   подразделов — одна группа, «Черный» — одно значение (по тексту). Это же закрывает старую ошибку с одинаковыми тегами.
5. **«Нет в наличии» → «Под заказ»**, такой товар можно положить в корзину и заказать (заказ — это заявка, как у nag).
   Это отменяет блокировку кнопки, сделанную 25.11.
6. **Публичные списки не кешируются** (было 2 минуты): правка в админке видна сразу; объём каталога мал для SQLite.
7. **Внутренний артикул** = префикс + номер товара (`CAM-00042`), без случайных чисел и без сбоев на тысячах товаров.
8. **Один адрес клиента для всех ограничений**: DRF `NUM_PROXIES = TRUSTED_PROXY_COUNT`; свой класс-обёртка удаляется.
9. **Пустой функционал удаляется**: неиспользуемые файлы, функции API, сторы, i18n (сайт только на русском, как nag),
   зависимости (lodash-es, motion, vue-i18n, django-filter, django-import-export и её зависимости).
10. **Стиль кода**: Prettier + ESLint (flat config) во фронте, Ruff (format + check) в бэкенде, команды в README;
    переводы строк файлов сохраняются (`endOfLine: auto`, ruff `line-ending = "auto"`).
11. **`alert()` в админке → всплывающие уведомления** админки.
12. **Документы товара**: PDF, DOC/DOCX, XLS/XLSX, ZIP, RAR до 20 МБ, проверка по сигнатуре файла, случайное имя.

## Значения
- Ярлыки статуса: `new` «Новинка», `promo` «Акция», `sale` «Распродажа».
- Наличие: не в наличии → «Под заказ»; количество не указано → «В наличии»; > 10 → «В наличии: 10+ шт»; иначе «В наличии: N шт».
- Скидка: `round((old_price − price) / old_price × 100)`, только если `old_price > price > 0`.
- Сортировки: `popular` «По популярности» (по умолчанию; число заказанных штук), `price` «Сначала дешевле»,
  `-price` «Сначала дороже», `new` «Новинки», `name` «По названию». Товары без цены — в конце при сортировке по цене.
- Товаров на странице: 20, 40, 80 (по умолчанию 20). Неверная страница → последняя существующая, не ошибка.
- Видимых групп фильтров — 5, значений в группе — 6 («Ещё N»).
