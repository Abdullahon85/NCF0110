# Аудит безопасности бэкенда NCF0110 — пункты 5–9

Дата: 2026-10-03. Продолжение `2026-10-03-security-audit.md` (п. 1–4 исправлены в ветке `security/p1-4`).

## 5. Спам и фейковые отзывы
- `ProductReview` / `ProductQuestion` создаются с `is_published=True` (дефолт модели) — отзыв сразу на странице товара, без модерации.
- Длина `text` (отзыв/вопрос), `message` (контакты), `comment` (заказ) не ограничена.
- Публичные POST (заказы, отзывы, вопросы, контакты) ограничены только общим анонимным лимитом 500/час, который обходится подменой `X-Forwarded-For`.
- Отзыв/вопрос к несуществующему slug → 500 (`Product.DoesNotExist`).
- Требование: новые отзывы и вопросы ждут модерации; длины ограничены; публичные POST имеют свой лимит по реальному IP; несуществующий товар → 404; покупатель видит, что отзыв ушёл на модерацию.

## 6. Загрузка файлов
- `validate_uploaded_image` доверяет `content_type` от клиента → можно загрузить HTML/SVG со скриптом, он раздаётся с домена бэкенда.
- `image/svg+xml` разрешён.
- `ProductViewSet.upload_image` (`/api/products/<slug>/upload-image/`) пускает любого авторизованного, не только staff.
- JWT-логин выдаёт токены не-staff пользователям.
- Требование: принимаются только реальные растровые изображения (проверка содержимого через Pillow): JPEG, PNG, GIF, WebP; SVG запрещён; имя файла на сервере не зависит от имени клиента; загрузка — только staff; токены — только staff.

## 7. Logout
- `admin_logout` ничего не делает: refresh-токен остаётся рабочим сутки.
- Смена пароля не отзывает уже выданные refresh-токены.
- Требование: logout отзывает переданный refresh-токен (даже если access уже истёк); смена пароля отзывает все refresh-токены пользователя.

## 8. DoS
- `?feature_1=..&feature_2=..` — каждый параметр добавляет JOIN; до 1000 параметров.
- `/api/products/by-feature/` отдаёт все совпадения без ограничения.
- `?taggroup_*` → `FieldError` → 500 (поле не существует).
- `?limit=-1` на `/api/categories/`, `/api/news/` → 500 (отрицательный срез).
- Требование: число JOIN ограничено; ответы ограничены по размеру; мусорные параметры не роняют сервер.

## 9. Хосты, зависимости, ссылки
- `ALLOWED_HOSTS`: `'*'` убран в п. 1, но нет `RENDER_EXTERNAL_HOSTNAME`; wildcard из env не запрещён.
- Django 5.2.5 и зависимости с известными уязвимостями (pip-audit, 2026-10-03): Django 33, Pillow 17, PyJWT 15, sqlparse 6, DRF 2, lxml 1, tablib 1. Набор без находок: Django 5.2.17, djangorestframework 3.17.2, pillow 12.3.0, pyjwt 2.15.1, sqlparse 0.6.0, tablib 3.10.0, lxml 6.1.3, asgiref 3.12.1 (остальные пины без изменений).
- `requirements.txt` в UTF-16.
- `Banner.link` принимает `javascript:` / `data:` и рендерится в `<a :href>`.
- Требование: хост Render добавляется автоматически, `'*'` отвергается; зависимости обновлены до набора без находок pip-audit; ссылки баннеров — только безопасные схемы.
- Вне объёма: `v-html` в About/News/Brand/Product (контент вводит только админ; экранирование может сломать HTML-форматирование на проде — нужна отдельная проверка контента).
